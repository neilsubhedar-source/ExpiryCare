# ExpiryCare 2.0 — Smart Expiry Tracker & Healthcare Website

Frontend prototype: **HTML + CSS + vanilla JavaScript** only (no frameworks, no build step).
Data is kept in the browser's `localStorage`. There is no backend, no real email and no AI —
"Smart Insight" is a set of simple rules applied to your own saved products.

## Run it
Open `index.html` in a browser (double-click). Register -> Login -> on an empty dashboard click
**Load demo data** to explore every feature. (Google Fonts is optional; a system font is used offline.)

## Pages
Public: `index`, `about`, `login`, `register`, `forgot-password`
Signed-in: `dashboard`, `inventory`, `add-product`, `product-details`, `edit-product`, `alerts`, `healthcare-guidance`, `profile`

## Files
- `css/styles.css` — design tokens + components + page styles (sections are numbered at the top)
- `js/app.js` — sections: STORAGE, AUTH, EXPIRY CALCULATIONS, ICONS, TOASTS, MODALS, DEMO DATA,
  DASHBOARD, INVENTORY, ADD/EDIT, DETAILS, ALERTS, PROFILE, GUIDANCE, RESPONSIVE, PAGE INITIALIZATION
- `assets/` — reserved for images/icons (icons are inline SVG, generated by `app.js`)

## Intelligence upgrade
The add-product page now includes supported-food barcode lookup, browser-native camera scanning where available, label image preview and a documented Flask integration hook for OCR/AI. Purchase and expiry dates may be left blank; such products remain in inventory with an explicit unknown/unidentified status and a separate review reminder. Product details show an evidence panel. Healthcare Guidance includes an API-connected chatbot interface and practical label/safety guidance. Chat uses the Flask endpoint and a clearly labelled offline knowledge base when no live AI provider is configured. Label images are sent to the Flask endpoint, which tries local Tesseract OCR; OCR output must be verified manually.

## Status rules (one place: EXPIRY CALCULATIONS in app.js)
Expired = date passed · Expiring Soon = 30 days or fewer left · Active = more than 30 days left. Missing dates are not classified as active and are not assigned a guessed expiry date.

## Retail Intelligence module (new)
Open **Retail Intelligence** from the dashboard navigation after signing in. It uses a separate `expirycareRetailV1` localStorage key and does not overwrite the existing `products` records. The fictional demo includes three branches, multiple batches per product, an expired batch, a near-expiry batch, and a batch with unknown expiry. Use **Load / reset fictional demo** to reset only this module's demo records; confirmation is required. **Export data JSON** exports this module's current records.

The module provides verified-date FEFO ordering, at-risk batch summaries, explainable clearance recommendations with approve/reject states, and a transfer lifecycle: Requested → Approved/Rejected → Dispatched → Received → Completed (with cancellation before dispatch). Approval reserves units, dispatch deducts source stock once, and receipt adds destination stock once. Duplicate pending requests for the same batch/destination are blocked. The browser-only workflow is a demonstrator, not secure authorization or multi-user concurrency control. Demand numbers are explicitly synthetic demo estimates. Unknown/unverified dates and expired batches are excluded from transfer eligibility.

## Canonical Flask backend
The active backend is the top-level `backend/` directory. From the project root, install `backend/requirements.txt` and run `python -m backend.app`. Follow the root `PBL_DEMO_GUIDE.md`. The main frontend inventory/account/retail data remains browser-local; do not describe it as fully Firestore-backed. Never commit service-account files or provider keys.

## Customer-facing store availability (frontend prototype)

Open `retail-catalog.html` to search the same `expirycareRetailV1` browser-local retail records used by Retail Intelligence. It counts only batches with a verified expiry date that has not passed and excludes reserved units. The catalog is public-facing and does not show transfer records, manager notes, or clearance controls. If retail demo data has not been initialized in that browser, it displays a clear no-data message instead of inventing availability.

All branch stock, prices, and demand shown in the retail prototype are fictional demo data unless explicitly replaced by the user. `localStorage` is not a secure database and does not provide multi-user synchronization, authorization, or transaction safety. The customer catalog is not a reservation, payment, or checkout service. Production use requires server-side access control, authoritative inventory APIs, and atomic transfer transactions.
